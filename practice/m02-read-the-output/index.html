Why read before you report?

A number with no unit, no baseline and no sign tells a board nothing. The product of your analysis is not 22,927. It is one sentence a CFO can act on. Reading the output the same way every time, in the same order, is how you stop yourself from misreading it, and how you catch a bug before the board does.

The reading order, for every output

StepAsk yourself
1UnitsWhat is the number measured in? Millions of dollars, thousands of trips, a percent? Say it with the unit.
2Compare to a baselineCompared with what? The other model, repeating last year, or guessing the average. R² below 0 means worse than guessing the average.
3Check the signError = actual minus forecast. Positive: forecast too low. Negative: forecast too high. Bias is the average of the signed errors.
4Size relative to the typical valueDivide the RMSE by a typical value (RMSE as a % of an average month). MAPE is already a percent. Is the miss big or small for this decision?
5The plain-English sentenceWho is it for, how big is the miss in their units, which way does it lean, and what should they do with it?

The four numbers in one line each

  • RMSE: a typical miss, in the data's own units. Big misses count more.
  • R²: how much of the ups and downs the model explains, compared with guessing the average. 1 is perfect, 0 is no better than the average, below 0 is worse.
  • MAPE: each month's miss as a % of that month's actual value, averaged.
  • Bias: the average miss with its sign. It shows which way the forecast leans.

What to look for

  1. Units. The RMSE row says $ millions. $22,927M is about $23 billion, not $22,927.
  2. Baseline. Compare the two models on the same test months. R² compares each model with a lazy forecast that predicts the test average ($700,707M) every month. R² below 0 means worse than that lazy forecast.

  5. Sentence. Turn it into a budget band: a projected $700B month, plus and minus one RMSE.

Watch out: a common misread

  • "R² 0.7577 means 76% accurate." No. R² is not accuracy. It says how much of the ups and downs the model explains compared with guessing the average.
  • "The bias is negative, so the model under-predicts." The sign is flipped. Error = actual minus predicted, so a negative bias means the forecast was too high. For a CFO this is the risky direction: revenue that never shows up.

  • The plus or minus one RMSE band is a rule of thumb for budgeting, not a formal confidence interval.

It is the end of 1959. A Miami travel agency wants to know how many international seats its clients will need each month of 1960. You have monthly international airline passengers (in thousands) from 1949 on. Before any fancy model, build the simplest honest forecast: each month of 1960 will look like the same month of 1959. Hold out the last 12 months of the data as the test set and measure how far off that rule is.

How to think about the plan

  1. A baseline is the forecast you could make in 30 seconds. Every model has to beat it, or it is not worth the work.
  2. This series has a seasonal pattern that repeats every 12 rows, so m = 12. The seasonal naive rule says: this month = the same month one year earlier.
  3. Split by time. Train on the earlier months, test on the last 12. The forecast may only use training data.
  4. RMSE is in the data's units (thousands of passengers) and punishes big misses. MAPE is in percent, so it is easier to say to a manager.

Think first

  • Why must the test set be the last 12 months and not 12 random months?
  • RMSE comes out in thousands of passengers and MAPE in percent. When would you quote each one to a manager?

import numpy as np
import pandas as pd

url = "https://raw.githubusercontent.com/c-marq/cap4767-data-mining/refs/heads/main/data/airline-passengers.csv"
df = pd.read_csv(url, parse_dates=["Month"], index_col="Month")
ts = df["Passengers"].asfreq("MS")
print(f"Rows: {len(ts)} | {ts.index[0]:%Y-%m} to {ts.index[-1]:%Y-%m}")

# Split by time: the last 12 months are the test set
train = ts.iloc[:-12]
test = ts.iloc[-12:]
print(f"Train: {len(train)} months | Test: {len(test)} months")

# Seasonal naive: each test month = the same month one year earlier
snaive = train.iloc[-12:].values

# Metrics
errors = test.values - snaive
snaive_rmse = np.sqrt(np.mean(errors ** 2))
snaive_mape = np.mean(np.abs(errors / test.values)) * 100

print(pd.DataFrame({"actual": test.values, "snaive": snaive}, index=test.index).head(3))
print(f"Seasonal naive RMSE: {snaive_rmse:.2f} thousand passengers")
print(f"Seasonal naive MAPE: {snaive_mape:.2f}%")

The travel agency manager asks: "Is a statistical model worth the extra work, or can we just repeat last year?" Use the same data and the same split as B1. Fit a SARIMAX model on the log of passengers, forecast the 12 test months, turn the forecast back into passengers, and compare its RMSE to the baseline from B1.

How to think about the plan

  1. Same split, same test months, same metric as B1. Only the model changes, so the comparison is fair.
  2. The swings in this series grow as the level grows. Taking the log makes the swings about the same size, which suits SARIMAX better.
  3. The order is fixed here, not picked by auto_arima, so everyone gets the same numbers. order=(0, 1, 1) means one regular difference and one moving-average term. seasonal_order=(0, 1, 1, 12) means one seasonal difference, one seasonal moving-average term, and m = 12.
  4. The model forecasts log passengers. Convert back with np.exp before you compute any metric, or the units are wrong.
  5. End with the manager sentence: which model, how big the typical miss, in what units, and the size of the improvement.

How to think about the plan

  1. Restate first: the decision (staffing, fuel), the number (the index, in index points), how far ahead (24 months) and the frequency (monthly).
  2. Look at the data: how many rows, which months, any gaps? A gap would break the seasonal pattern.
  3. Monthly data means the pattern repeats every 12 rows, so m = 12.
  4. A 24-month test window holds out two full seasonal cycles. Train on everything before it.
  5. The baseline now has to cover 24 months from 12 training months, so repeat the last 12 training months twice. np.tile does that.

import numpy as np
import pandas as pd

url = "https://raw.githubusercontent.com/c-marq/cap4767-data-mining/refs/heads/main/data/us-electricity-production-monthly.csv"
df = pd.read_csv(url, parse_dates=["Month"], index_col="Month")
ts = df["Production"].asfreq("MS")

# Look at the data
print(f"Rows: {len(ts)} | {ts.index[0]:%Y-%m} to {ts.index[-1]:%Y-%m}")
print(f"Missing values: {ts.isna().sum()}")

# Monthly data, a pattern that repeats every 12 rows
m = 12

# Split by time: the last 24 months are the test set
n_test = 24
train = ts.iloc[:-n_test]
test = ts.iloc[-n_test:]
print(f"Train: {len(train)} months | Test: {len(test)} months ({test.index[0]:%Y-%m} to {test.index[-1]:%Y-%m})")

# Seasonal naive: repeat the last 12 training months, twice
snaive = np.tile(train.iloc[-m:].values, n_test // m)

# Metrics in index points
errors = test.values - snaive
rmse = np.sqrt(np.mean(errors ** 2))
mape = np.mean(np.abs(errors / test.values)) * 100

print(f"Seasonal naive RMSE: {rmse:.2f} index points")
print(f"Seasonal naive MAPE: {mape:.2f}%")
print(f"Bar to beat: RMSE under {rmse:.2f}")

"To forecast the 2017 and 2018 index, any model has to beat repeating the last training year, which misses by about 5.13 index points (RMSE), or 3.87% in a typical month."

Watch out

You may be tempted to write ts.shift(12) and use the last 24 values. For the second year that copies a value from the test set itself, not from training. Here it only moves the RMSE from 5.13 to 5.15, but the method is still wrong: a forecast may only use data from before the first test month. np.tile on the training months keeps it honest.
